## 2. 五个阶段（每阶段都有验收标准，别跳）

### P0 架构地基（1–2 周）
**产出**：确定性内核 + Facts 契约 + 金标准测试集；流协议（含 seq 续传）；工具注册表；额度/错误码。
**验收**
1. 内核在 **≥500 条已知命例**上与参考实现逐字段一致（含立春/子时/真太阳时/夏令时边界用例）；
2. 断线续传：`from_seq` 重连后**无重复、无缺口**（骨架里已有这条 e2e 测试）；
3. 额度错误码全部有测试覆盖，客户端只按 code 渲染。

### P1 单点闭环 MVP（2–3 周）
**产出**：排盘表单 → Facts → 一次流式 AI 解读 → 保存记录 → 配额生效。
**验收**：输入到首字 p95 < 2s；整段完成 p95 < 40s；额度耗尽时前端渲染正确文案而非报错页。

### P2 长文交付物（2–4 周）
**产出**：10 章报告（章节计划 → 逐章生成 → 进度语义 → 异步邮件 → 可重放）。
**验收**：单份成本与时长在预算内；中途失败可续跑且**不重复计费**；同一 Facts 的重复请求命中缓存。

### P3 工具型 Agent（3–4 周）
**产出**：分域工具注册 + `reasoning`/`phase_change`/`tool_call`/`tool_result` 流式 UI + 可管理记忆。
**验收**：每条回答都能**列出它用了哪些工具与哪些事实**（可审计）；记忆可改/删/清空，且**不影响**确定性计算。

### P4 内容与增长（持续）
**产出**：长尾内容页 + GEO（放开 AI 爬虫并度量 AI 来源）+ 归因与埋点。
**验收**：索引页数、AI 助手引用量、注册转化率三条曲线可看。

## 3. 架构蓝图：两家验证过的"正确解"

```
客户端(Web/WebView)
  └─ 流式渲染：reasoning 折叠区 / 工具调用进度 / 正文分章
边缘(CDN/WAF) ── 静态 + 反爬 + 限速
API
  ├─ 内核服务：纯函数 computeFacts(input) → Facts（无 LLM）
  ├─ 编排(Narrator)：读 Facts → 规划 → 调工具 → 生成正文（流）
  ├─ 额度服务：server-authoritative entitlements + usage ledger
  └─ 长文队列：章节任务 + 断点续跑 + 邮件送达
存储：profiles(生辰,加密) / conversations / frames(seq) / reports / memories / content
```

**六条不变量（写进代码注释与测试，别只写在文档里）**

| # | 不变量 | 为什么 |
|---|---|---|
| I1 | **模型不计算历法**；所有干支/节气/神煞来自内核 | 两家都这么做；LLM 换算历法必错 |
| I2 | 每个结论都能**指回 Facts 字段**，UI 并列展示事实与散文 | 用户可审计，是命理品类的信任来源 |
| I3 | 流有 `seq`、可续传、可重放；**幂等键 = messageId/request_id** | 断网"接着写"；重试不重复计费 |
| I4 | 额度**服务端权威**，客户端缓存只做首屏 | 防绕过；实测两家都这样 |
| I5 | 记忆可改/删/清空，且**不改变确定性计算** | 合规 + 用户信任 |
| I6 | **不伪造**：不编命盘、不编卦象、不编牌阵；能力边界写进产品文案 | 两家都把它当卖点，不是免责声明 |

## 5. 成本与延迟（必须提前算，否则 P2 会崩）

**单份 10 章报告的量级**（按每章 1.5–3k 输出 token、facts+指令 2–4k 输入估）：

```
cost ≈ Σ_chapters ( input_tokens × price_in + output_tokens × price_out )
再乘：重试系数(1.1~1.3) + 用神判定等前置调用
```

**必须做的四件事**
1. **异步 + 邮件送达**：5–10 分钟的生成不要让人守着页面（两家都是邮件）。
2. **缓存键 = `hash(facts) + chapter + prompt_version`**：同一命例同章不重复付费。
3. **分层模型**：小模型/规则做用神候选与意图路由，大模型只执笔（省钱且稳）。
4. **熔断**：单用户日/月上限 + 全局日预算 + 超额降级（排队/降模型）。

## 7. 风险与合规

| 风险 | 处理 |
|---|---|
| 内容定位 | 条款与 UI 明确"文化娱乐，非医疗/投资/法律/心理建议"；不承诺预测准确性 |
| 渠道规则 | 订阅与虚拟商品受应用商店抽成与审查（两家都注明"权益仅限购买平台"）；Web 端可自营支付 |
| 敏感个人信息 | 生辰/地点是最敏感的一类：加密存储、最小化采集、可导出可删除、**不进日志**（两家都在文案里强调隐私） |
| 内容合规 | 生成内容需审核（涉迷信/医疗断言分层处理），长尾页人工兜底 |
| 成本 | 见 §5 的缓存 + 分层 + 熔断 |
| 幻觉 | I1/I2/I6 三条不变量 + 回归测试集 |

## 7bis. 交节精度（✅ 已收口：v3 达标）

**现状态（v3 实测）**：换成**完整 VSOP87D 地球级数**后，50 点公开发布节气集合上的
**最大偏差 9.6 秒**（平均 4.7 秒）；独立第二套 17 点基准最大 17.3 秒。
相对 v2（8.8 分钟）改善约 55 倍，相对 ≤2 分钟目标有约 12 倍余量。
2024 立春两侧各 1 分钟的年柱/月柱严格用例已通过（`16:25 → 癸卯`、`16:28 → 甲辰`）。

| 版本 | 最大偏差 | 状态 |
|---|---|---|
| v1 低精度公式（含 mod-360 bug） | 970 s | 首次审计 |
| v2 开普勒求解 + 经验标定 | 528 s | 未达标 |
| **v3 VSOP87D（1080 + 997 项，机械提取自公开表）** | **9.6 s** | **达标** |

**P2 三条收口标准的状态**

1. ✅ 50 点集合最大偏差 ≤2 分钟 → 实测 **9.6 s**（出处与提取方法记录在 [verify/kernel-accuracy.md](verify/kernel-accuracy.md)）；
2. ✅ `TERM_ACCURACY_SECONDS` 下调至 **60 s**（约 6 倍于实测最大值，刻意保守），且严格边界用例转绿；
3. ✅ 交节路径**不再依赖经验标定常数**：VSOP87D 路径无任何拟合项；`astro.mjs` 里的
   `CALIBRATION_OFFSET_DEG` 仅存于遗留的均时差辅助函数中，**已不参与任何柱子判定**
   （如需彻底清除，可把均时差也切到 VSOP87 黄经，但均时差本身只影响真太阳时，误差 <1 秒）。

**保留的诚实性机制（不因精度提升而拆除）**：`termAccuracySeconds` 与 `boundaryUncertainty`
仍在，窗口内命例仍会被标记——只是窗口从 528 s 收窄到 60 s。这三条由
`build/verify/kernel-crosscheck.mjs` 的门禁守着（不低报误差、窗口内必标记、远离边界不狼叫）。

## 8. 现在就能做的三件事

1. **跑起来看**：起服务并配好持久化，用 curl 过一遍三种流（命令见 [README](README.md)）；
   真实模型只需设 `SHENSHA_LLM_KEY`。
2. **冻结协议 v1**：把 [PROTOCOL.md](PROTOCOL.md) 当契约，前后端按它对接（改协议要升版本号）。
3. **把金标准从 200 例扩到 1000 例**：内核已用 5 个外部锚点 + 50 点节气表验证（见 [verify/](verify/)），
   但"唯一不能出错的部分"值得更宽的对照集——建议纳入近百年节气边界、闰秒/时区立法变更、
   以及 23:00 换日口径的争议命例。
